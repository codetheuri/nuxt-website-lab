Welcome to your new Nuxt 4 project (`nuxt-website-lab`)!

While `vue-component-lab` was a Vue 3 SPA boilerplate for internal admin systems, this new repo will become a reusable **Nuxt 4 Website & SEO Boilerplate** for public company websites, landing pages, service catalogs, and blogs.

Before writing code, notice how Nuxt 4 is different from plain Vue + Vite:
- Frontend files live inside the `app/` folder (`app/pages/`, `app/components/`, `app/layouts/`, `app/composables/`, `app/app.vue`).
- Nuxt uses **file-based routing** (creating `app/pages/about.vue` automatically creates `/about` — you do NOT write a `router/index.js` file!).
- Components, composables, and Vue APIs (`ref`, `computed`, `useRoute`, `useSeoMeta`) are **auto-imported** by Nuxt.
- Public environment variables start with `NUXT_PUBLIC_` (configured in `nuxt.config.ts` via `runtimeConfig`) instead of `VITE_`.

Here is your Milestone 1 task:

1. Configure Styling, Runtime Config, and Central Site Config
- Set up clean modern styling for a public marketing website (install Tailwind CSS or Bootstrap — Tailwind CSS is strongly recommended for marketing websites).
- Configure `runtimeConfig.public` in `nuxt.config.ts` to read `NUXT_PUBLIC_SITE_NAME`, `NUXT_PUBLIC_SITE_URL`, and `NUXT_PUBLIC_API_BASE` (see `.env.example`), plus a default HTML head `<title>` template and meta description.
- Create a single site configuration file (`app/config/site.ts`) that holds the brand name, tagline, main navigation links (`Home`, `Services`, `Blog`, `About`, `Contact`), footer links, contact details, and social links so spinning up a new client website only requires editing one file.

2. Build the Website Layout Shell (`app/layouts/default.vue`) & Root `app/app.vue`
- Update `app/app.vue` to render `<NuxtLayout><NuxtPage /></NuxtLayout>` (replacing `<NuxtWelcome />`).
- Create `app/layouts/default.vue` with:
  - A sticky, responsive top **Header Navbar** reading links from `app/config/site.ts`, highlighting the active route, with a working mobile hamburger menu drawer on small screens and a **Dark / Light theme toggle** (make sure it works cleanly with SSR without causing hydration mismatch errors!).
  - A clean multi-column **Footer** reading company info, quick links, and copyright year from `app/config/site.ts`.

3. Build the Initial Pages with Dynamic SEO Metadata (`useSeoMeta`)
Create the following pages inside `app/pages/` using file-based routing, and set unique SEO metadata (`title`, `description`, `ogTitle`, `ogDescription`) on every page using `useSeoMeta()`:
- **Home (`/`):** Clean Hero section (headline, subtitle, primary & secondary CTA buttons), Services/Features overview grid (3–6 cards), Key Stats or Trust section, Testimonials section, and a Call-To-Action banner linking to `/contact`.
- **About (`/about`):** Company story, mission/values cards, and team grid.
- **Services (`/services`) & Blog (`/blog`):** Starter listing pages (we will connect them to Nitro `server/api/` endpoints and dynamic `[slug]` pages in Milestone 2).
- **Contact (`/contact`):** Contact details + a styled inquiry form (Name, Email, Subject, Message) with client-side validation.

4. Create a Custom Branded Error Page (`app/error.vue`)
- Build `app/error.vue` so visiting a non-existent URL like `/does-not-exist` displays a clean branded `404` page with a button that uses Nuxt's `clearError({ redirect: '/' })` to safely return home.
